## Teaching Contract

The priority is making decisions with `if`, not memorizing a networking toolbox. Demonstrate the ping/traceroute warm-up from your classroom SSH session, then have learners connect, follow the web-request path from DNS to HTTP, and build the checker.

Learners already have SSH, Micro, assignments, quoting, `printf`, streams, and a working S5 report. Git homework is not a prerequisite. Retrieve those skills briefly; do not reteach S5 or overwrite a learner's report script.

Three outcomes:

1. Distinguish name lookup, ICMP echo replies, and HTTP responses.
2. Inspect statuses, headers, and a body with curl.
3. Explain and run a checker for the homepage and report, including a report-404 repair and a failed-request branch.

`for` repeats the two paths. Traceroute is a brief warm-up demonstration; `while` stays in the optional appendix. Raw HTTP over netcat stays in S7.

## Demonstration Notes

- State the viewpoint before interpreting evidence. `host` queries DNS; curl can resolve through `/etc/hosts`.
- Present ping and traceroute as diagnostic tools, not required steps in opening a page. Use the same numeric public address for both, then introduce the web-request diagram.
- Teach status families before examples. `3xx` is broader than "the resource moved": `304` concerns caching.
- `HEAD 200` is a successful request, not proof that the HTML is correct or freshly generated. Let learners find their actual report heading in `GET` output.
- Make `if` work on one path before adding `for`. Each stage belongs in the same checker file.
- Keep S5's `set -euo pipefail` from the first script. Its `page="$1"` requires an argument; pass `""` for the homepage. Before explicit exit-code capture is added, a curl failure stops the script; afterwards it prints the diagnostic and continues to the next page.
- Explain `==` versus assignment `=`, both delimiters `[[`/`]]`, then `elif` and `&&`. Keep examples quoted.
- Reset `curl_exit_code=0` on every iteration, capture HTTP in `status`, and use `|| curl_exit_code=$?` to record failure without triggering `set -e`. The outer `if [[ "$curl_exit_code" -eq 0 ]]` checks curl's exit code; the inner `if` interprets HTTP. Do not turn expected `404` responses into transport failures with `-f`.
- The checker prints messages for humans. Do not use its exit code as the live-health result or claim it is production monitoring.

## Predict, Then Check

Use the hypothetical cases in the [final exercise](../sessions/S06/self-study.md#exercise-6-predict-then-check). Learners read the unchanged checker and predict each diagnostic. Ask why homepage and report `404` cases differ, and why a curl failure skips the HTTP decision. Then run the checker on real pages and follow any repair advice. Do not inject statuses or delete a working page to create a failure.

For a real `404`, request an unused filename at the prompt. For a request failure, use the reserved `.invalid` example from the slides with its three-second timeout. Neither requires changing the checker. A proxy may respond; use the observed result rather than promising a specific error message.

Use the provided report generator when needed; leave learners' committed S5 versions in `~/src` intact. `cp -i` lets them keep an existing working copy in `~/scripts`.

## Guide And Completion

Three live gates: observe DNS command, observe homepage header command, inspect checker source. They do not execute learner scripts as the bot. The instructor checks explanations and real outputs.

Four reinforcement quests: DNS answer line, ping summary (including no replies), HTTP status line/header, and checker source. Run `guide now` before submitting quest evidence. Use `guide answer 'observed text'` followed by `guide check` when asked.

## Recovery

- Missing command or privileges: operator handles provisioning before class.
- Missing report generator: copy the provided script; do not reconstruct the learner's website.
- Syntax error: `bash -n`, inspect delimiters, then `bash -x` after parsing succeeds.
- Report `404`: regenerate Markdown, rebuild HTML, retest. Homepage `404`: inspect `index.md`, then rebuild.
- TLS, `403`, `500`, or `502`: keep the exact output and escalate shared-service issues.
- Wrong URL twice: inspect `url="$base_url/$page"` inside the loop.
- Guide source pass but failed page: repair the page; guide did not assert network success.

Do not reset progress, remove source, or repair learner files as root.
